# Project working instructions

## Keep graphics consistent

- New and replacement product, department, collection and promotional artwork must match the existing polished 3D assets. Inspect relevant images in `assets/products/`, `assets/categories-3d/` and `assets/banners/` before creating artwork.
- Product images use realistic 3D studio rendering, complete products in three-quarter perspective, detailed materials, soft upper-left lighting, subtle contact shadows and a clean near-white square background. Match the established framing and visual scale.
- Department artwork uses dimensional, polished product compositions with the established blue, teal and green accents and transparent backgrounds. Supply actual 3D raster artwork for new departments.
- Do not substitute flat SVG illustrations, emoji, CSS drawings or generic line icons for primary product or department artwork. Existing SVGs remain appropriate for interface controls and data-saver fallbacks.
- Use the imagegen skill for generated raster artwork. Save optimized production assets in the workspace, update their catalogue references, and check visual consistency before finishing. Keep sample labels in the interface rather than baking text into product images.

## Clean up after each task

- Before finishing, remove temporary previews, screenshots, contact sheets, browser profiles, scratch scripts, and other artifacts created solely to implement or verify the task, including files ignored by Git.
- Keep production assets and intentional documentation deliverables. Do not leave temporary previews behind simply because they are ignored by Git or excluded from publication.
- Check the workspace for task-created leftovers as well as checking `git status`. Verify paths before deleting anything, and never delete unrelated user files or active browser profiles.
- Retain a preview only when the user explicitly asks for it as a deliverable.
